# Finance Advisor V8 — Workflows and Guardrail Integration

## Architectural Relationship: V7 Workflows vs V8 Guardrails

In **Milestone 7 (V7)**, the application focused on **Orchestration**:
- How to structure multi-agent pipelines (Sequential 5-stage chain, Parallel fan-out/in, Iterative Critic Loop).

In **Milestone 8 (V8)**, the application focuses on **Protection and Control**:
- How to enclose agents and workflows with deterministic lifecycle boundaries:
  - Input interception (BeforeAgent)
  - Tool interception (BeforeTool)
  - Fact capture (AfterTool)
  - Model interception (AfterModel)

---

## Combining Workflows and Guardrails

When V7 deterministic workflows (`run_sequential_research_workflow`, `run_parallel_portfolio_research_workflow`, `run_critic_loop_research_workflow`) are invoked under V8:
1. `ToolOperationGuard` validates that the workflow tools themselves are permitted research operations.
2. Individual stock queries within the workflow pass through `TickerValidator`.
3. Tool outputs captured during workflow execution feed into the `EvidenceStore`.
4. Final synthesis reports generated by the workflows are audited by `AfterModelGuardrail` (checking for offensive language, verifying factual figures, and ensuring the mandatory regulatory disclaimer).
